# 字幕校对台 · Live Subtitle QC Console

面向直播运营团队的字幕校对工作台。现场字幕事件持续推送，网络抖动会造成**乱序、重复**，机器修订还可能**覆盖人工已确认的内容**——本工作台把这些情况全部可视化，并把最终裁决权交给运营人员。

字幕机的源时钟还会逐渐**偏离导播台节目时钟**：开场对齐后，后段字幕仍可能提前或滞后。工作台提供**节目时钟漂移校准**——用若干锚点拟合非固定偏差，让运营看清漂移并预览校准后的播出效果。

全部数据在浏览器本地模拟，不依赖任何后端服务。

## 功能一览

- **三栏直播工作台**：直播预览（ON AIR 监视器 + 待播队列）、字幕时间线、事件流同屏呈现
- **乱序补齐**：字幕按序号排列，缺失片段留下明显空位（斜纹 + 虚线框 + 文字说明）；晚到片段自动补回
- **重复去重**：同一事件 ID 重发、或不同事件内容完全相同，都只记录日志，绝不生成第二条字幕
- **版本更新**：未锁定片段收到更高版本机器修订时直接应用，过期版本被忽略
- **锁定冲突**：人工修改并锁定后，机器修订不再静默覆盖，转为待裁决冲突——由运营选择「保留人工版本」或「接受机器修订」
- **节目时钟漂移校准**：每条字幕携带源入点/出点；为至少两条已确认片段录入节目时间码作为锚点，系统在锚点间分段线性映射、范围外沿最近一段外推，拟合非固定偏差
- **校准面板**：原始时间 / 校准时间 / 当前偏移对照表、漂移曲线（偏移随节目时间变化的折线）、可拖动播放头实时预览校准后的字幕切换
- **锚点身份稳定**：锚点按字幕序号绑定——片段收到更高版本修订后锚点保留，重复事件不产生副本，晚到补齐后时间线与预览自动重算
- **本地持久化**：校准方案与播放头位置保存在浏览器 localStorage，刷新后自动恢复；重放事件流不会清掉校准方案
- **可稳定重放的“网络抖动”场景**：内置 `101 → 103 → 103(重复) → 102(晚到) → 102 的机器修订 v2`，支持播放 / 暂停 / 单步 / 0.5–4× 倍速 / 重放；每次重放从干净状态开始，相同操作必然得到相同结果
- **不只靠颜色区分状态**：播出中、缺口、重复、冲突、锁定均有图标 + 文字徽标（缺口另有斜纹图案），色盲友好

## 运行方式

要求 Node.js ≥ 18。

```bash
npm install       # 安装依赖
npm run dev       # 开发模式（默认 http://localhost:5173）
npm test          # 运行自动化测试（Vitest，38 个用例）
npm run build     # 生产构建（tsc 类型检查 + vite 打包到 dist/）
npm run preview   # 预览生产构建产物
```

## 快速体验：复现一次“锁定冲突”

1. 点击底部「▶ 播放」，观察 `#101` 到达、`#103` 乱序到达留下 `#102` 缺口、重复 `#103` 被去重、`#102` 晚到自动补回；
2. 在 `#102` 补齐后（+4.5s）、修订到达前（+10s）点击「⏸ 暂停」；
3. 在时间线上「✏️ 修改」`#102` 的文本，然后点击「🔒 锁定」；
4. 点击「▶ 播放」继续，机器修订 v2 到达 → 顶部出现**待裁决冲突**面板；
5. 选择「✋ 保留人工版本」或「🤖 接受机器修订」，观察时间线与事件流的变化；
6. 随时点击「↺ 重放」回到干净状态重新开始；也可以用「⏭ 单步」逐事件精确推进。

## 快速体验：校准一次“时钟漂移”

1. 播放场景，待 `#101`、`#102`、`#103` 全部到达（源入点分别为 00:00.0 / 00:02.4 / 00:04.8）；
2. 在「⏱️ 节目时钟漂移校准」面板：选择 `#101`，录入节目时间码 `0`，保存；再选择 `#103`，录入 `5`（即源时钟每 4.8s 走快 0.2s）；
3. 观察片段时间对照表：`#102` 的校准入点自动算为 `00:02.5`，时间线行同步出现绿色「→ 节目」徽标；
4. 看漂移曲线：偏移从 0 线性爬到 +0.2s——偏差不是固定值，统一加减偏移量修不了它；
5. 拖动播放头，监视器按校准后的节目时间切换字幕，并显示当前偏移；
6. 试试非法锚点：给 `#102` 录入 `10`（晚于 `#103` 的 5s），保存被拒绝并指出与 `#103` 冲突，当前方案不受影响；
7. 刷新页面：校准方案与播放头位置原样恢复；「↺ 重放」只清事件数据，校准方案保留。

## 架构说明

```
src/
├── types.ts            领域模型（事件 / 片段 / 冲突 / 校准锚点 / 日志 / 状态）
├── calibration.ts      校准核心：锚点校验、分段线性映射与外推、逆映射、时间码解析（纯函数）
├── consoleReducer.ts   纯函数状态机：去重、补齐、版本裁决、锁定冲突、锚点方案校验、重置
├── selectors.ts        派生数据：缺口、当前播出、待播队列、校准后片段时间、播放头命中
├── scenario.ts         内置“网络抖动”场景脚本（逻辑时间戳 + 源时间码，确定性数据）
├── player.ts           播放器：播放/暂停/单步/倍速/重放，调度器与时钟可注入
├── persistence.ts      浏览器本地持久化：校准方案与播放头位置（无 localStorage 时安全降级）
├── useSubtitleConsole.ts  React 装配层（useReducer + Player 单例 + 本地恢复/保存）
├── components/         界面组件（预览 / 时间线 / 事件流 / 冲突面板 / 校准面板 / 播放控制）
└── __tests__/          Vitest 测试
```

**确定性设计**（“相同操作 → 相同结果”的保证）：

- reducer 与校准映射都是纯函数，不读时钟、不含随机数；事件自带逻辑时间戳与源时间码；
- 播放器的调度器与时钟均可注入，测试中用手动时钟同步驱动；
- 「重放」= `reset` 动作（清空事件数据，保留校准方案这一控制台配置）+ 从头调度同一场景脚本。

**关键规则**：

| 情况 | 行为 |
| --- | --- |
| 相同事件 ID 再次到达 | 记「重复」日志，状态不变 |
| 同序号同版本同文本 | 记「重复」日志，状态不变 |
| 更低版本到达 | 记「过期」日志，状态不变 |
| 更高版本 + 未锁定 | 直接应用修订（若覆盖了未锁定的人工修改，会在日志中注明） |
| 更高版本 + 已锁定 | 登记待裁决冲突，人工内容原样保留 |
| 裁决「保留人工」 | 丢弃该机器修订，片段维持锁定 |
| 裁决「接受机器」 | 应用修订内容并解除锁定，片段交还机器流 |
| 锚点落在已修订片段上 | 锚点按字幕序号绑定，修订不清除锚点 |
| 锚点源时间/节目时间未严格递增 | 方案被拒，当前有效方案原样保留，日志与面板均指出冲突位置 |
| 重放 / 刷新页面 | 事件数据清零；校准方案与播放头位置保留在浏览器本地 |

**校准映射规则**：锚点按源时间排序后分段线性插值；源时间早于首个锚点沿首段斜率外推，晚于末个锚点沿末段斜率外推；仅 1 个锚点时退化为整体平移；0 个锚点时为恒等映射。合法方案要求源时间与节目时间都严格递增，保证映射单调、不打乱字幕顺序。

**播出规则**：当前播出字幕是从最小序号起连续完整的最长前缀末尾——缺口之后的片段即使已到达也只进入待播队列，直到缺口补齐。

## 自动化测试

`src/__tests__/` 共 38 个用例，覆盖需求要求的全部场景：

- **乱序补齐**：缺口出现/消失、播出序号不越过缺口、补齐日志
- **重复去重**：事件 ID 级去重、内容级去重，均不产生第二条字幕
- **版本更新**：未锁定片段应用修订、过期版本被忽略
- **锁定冲突**：不静默覆盖、锁定时禁止编辑、「保留人工」与「接受机器」两种裁决
- **插值与外推**：锚点间线性插值、首末段外推、多锚点不同斜率、单锚点平移、零锚点恒等、映射互逆
- **非法锚点**：节目时间/源时间未严格递增、同序号多锚点均被拒并指出冲突位置；非法方案不覆盖当前有效方案
- **修订身份保持**：更高版本修订后锚点保留且映射不变、重复事件不产生锚点/片段副本、reset 保留校准方案
- **校准后预览**：片段时间对照计算、播放头命中/间隙判定、晚到补齐后时间线与预览自动重算
- **无残留重放**：reset 后与初始状态逐位相等；同操作序列重放结果一致；播放器两轮完整播放终态一致
- **播放器行为**：按时间表投递、暂停结算剩余时间、倍速重排程、单步与播放混用
