# 字幕校对台 · Live Subtitle QC Console

面向直播运营团队的字幕校对工作台。现场字幕事件持续推送，网络抖动会造成**乱序、重复**，机器修订还可能**覆盖人工已确认的内容**——本工作台把这些情况全部可视化，并把最终裁决权交给运营人员。字幕机时钟还会逐渐**偏离节目时钟**，工作台提供锚点校准，让运营看清并修正这种非固定偏差。

全部数据在浏览器本地模拟，不依赖任何后端服务。

## 功能一览

- **三栏直播工作台**：直播预览（ON AIR 监视器 + 待播队列）、字幕时间线、事件流同屏呈现
- **乱序补齐**：字幕按序号排列，缺失片段留下明显空位（斜纹 + 虚线框 + 文字说明）；晚到片段自动补回
- **重复去重**：同一事件 ID 重发、或不同事件内容完全相同，都只记录日志，绝不生成第二条字幕
- **版本更新**：未锁定片段收到更高版本机器修订时直接应用，过期版本被忽略
- **锁定冲突**：人工修改并锁定后，机器修订不再静默覆盖，转为待裁决冲突——由运营选择「保留人工版本」或「接受机器修订」
- **时钟漂移校准**：每条字幕带源入点/出点；为至少两个已确认片段录入节目时间码作为锚点，系统在锚点间**分段线性映射**、范围外**沿最近一段外推**，把源时间轴换算成节目时间轴
- **校准面板**：校准对照表（原始时间 / 校准时间 / 当前偏移）、漂移曲线（SVG，锚点间实线、外推虚线）、可拖动播放头——拖动即可预览校准后的字幕切换
- **锚点按序号绑定**：同一片段收到更高版本修订后锚点保留并自动跟随新源入点；重复事件不产生副本；晚到补齐后时间线与预览自动重算
- **非法锚点防护**：源时间与节目时间都必须严格递增，非法录入不会覆盖当前有效方案，并明确指出冲突位置（涉及哪两个锚点、哪一侧时间）
- **本地持久化**：校准方案与播放头位置保存在浏览器 localStorage，刷新自动恢复；重放场景不会清除校准
- **可稳定重放的“网络抖动”场景**：内置 `101 → 103 → 103(重复) → 102(晚到) → 102 的机器修订 v2`，支持播放 / 暂停 / 单步 / 0.5–4× 倍速 / 重放；每次重放从干净状态开始，相同操作必然得到相同结果
- **不只靠颜色区分状态**：播出中、缺口、重复、冲突、锁定均有图标 + 文字徽标（缺口另有斜纹图案），色盲友好

## 运行方式

要求 Node.js ≥ 18。

```bash
npm install       # 安装依赖
npm run dev       # 开发模式（默认 http://localhost:5173）
npm test          # 运行自动化测试（Vitest，41 个用例）
npm run build     # 生产构建（tsc 类型检查 + vite 打包到 dist/）
npm run preview   # 预览生产构建产物
```

## 快速体验：复现一次“锁定冲突”

1. 点击底部「▶ 播放」，观察 `#101` 到达、`#103` 乱序到达留下 `#102` 缺口、重复 `#103` 被去重、`#102` 晚到自动补回；
2. 在 `#102` 补齐后（+4.5s）、修订到达前（+10s）点击「⏸ 暂停」；
3. 在时间线上「✏️ 修改」`#102` 的文本，然后点击「🔒 锁定」；
4. 点击「▶ 播放」继续，机器修订 v2 到达 → 顶部出现**待裁决冲突**面板；
5. 选择「✋ 保留人工版本」或「🤖 接受机器修订」，观察时间线与事件流的变化；
6. 随时点击「↺ 重放」回到干净状态重新开始；也可以用「⏭ 单步」逐事件精确推进。

## 快速体验：校准一次“时钟漂移”

1. 播放场景让 `#101`、`#102`、`#103` 全部到达（每条片段在时间线上都标注了源入点/出点）；
2. 在「🎯 时钟漂移校准」面板中，把 `#101` 锚定到节目时间 `0.0` 秒、`#103` 锚定到 `12.9` 秒（机器时钟到后段已偏慢 0.9 秒）；
3. 观察**漂移曲线**（偏移随源时间线性增长，范围外虚线外推）与**校准对照表**（`#102` 被自动插值到 6.5s–13.0s）；
4. 拖动**播放头**，预览条上各片段按校准窗口排布，读出框实时显示该节目时刻播出的字幕；
5. 试试非法录入：把 `#102` 锚定到 `13.0` 秒（晚于 `#103` 的 12.9 秒）——方案不会被覆盖，面板与事件流都会指出冲突位置；
6. 修改并锁定 `#102` 等修订到达后裁决，或点击「↺ 重放」——锚点始终保留；刷新页面，校准方案与播放头位置自动恢复。

## 架构说明

```
src/
├── types.ts            领域模型（事件 / 片段 / 冲突 / 锚点 / 日志 / 状态）
├── calibration.ts      漂移校准纯函数：锚点联结、严格递增校验、分段线性映射与外推
├── consoleReducer.ts   纯函数状态机：去重、补齐、版本裁决、锁定冲突、锚点管理、重置
├── selectors.ts        派生数据：缺口、当前播出、待播队列、校准时间线、播放头命中等
├── scenario.ts         内置“网络抖动”场景脚本（逻辑时间戳 + 源入点/出点，确定性数据）
├── player.ts           播放器：播放/暂停/单步/倍速/重放，调度器与时钟可注入
├── useSubtitleConsole.ts  React 装配层（useReducer + Player 单例 + localStorage 持久化）
├── components/         界面组件（预览 / 时间线 / 事件流 / 冲突面板 / 校准面板 / 播放控制）
└── __tests__/          Vitest 测试
```

**确定性设计**（“相同操作 → 相同结果”的保证）：

- reducer 是纯函数，不读时钟、不含随机数；事件自带逻辑时间戳；
- 校准映射同样是纯函数：锚点只存「序号 → 节目时间」，源时间由片段当前源入点派生，修订、补齐、重放后自动重算；
- 播放器的调度器与时钟均可注入，测试中用手动时钟同步驱动；
- 「重放」= `reset` 动作（清空事件流状态）+ 从头调度同一场景脚本；校准锚点与播放头是会话级设置（描述时钟关系，与事件流无关），重放时保留。

**关键规则**：

| 情况 | 行为 |
| --- | --- |
| 相同事件 ID 再次到达 | 记「重复」日志，状态不变 |
| 同序号同版本同文本 | 记「重复」日志，状态不变 |
| 更低版本到达 | 记「过期」日志，状态不变 |
| 更高版本 + 未锁定 | 直接应用修订（若覆盖了未锁定的人工修改，会在日志中注明） |
| 更高版本 + 已锁定 | 登记待裁决冲突，人工内容原样保留 |
| 裁决「保留人工」 | 丢弃该机器修订，片段维持锁定 |
| 裁决「接受机器」 | 应用修订内容与源时间并解除锁定，片段交还机器流 |
| 锚点少于 2 个 | 校准未启用，预览按源时间展示 |
| 锚点 ≥ 2 个且合法 | 锚点间分段线性映射，范围外沿最近一段斜率外推 |
| 源/节目时间未严格递增 | 拒绝录入并保留当前有效方案，面板与日志指出冲突位置 |
| 同一片段收到修订 | 锚点按序号保留，源时间自动跟随片段当前源入点 |
| 重复事件到达 | 只记日志，锚点与校准方案不受影响 |
| 晚到补齐 / 锚点增删 | 校准时间线、漂移曲线与播放头预览自动重算 |

**播出规则**：当前播出字幕是从最小序号起连续完整的最长前缀末尾——缺口之后的片段即使已到达也只进入待播队列，直到缺口补齐。

**持久化**：校准锚点与播放头位置以 `subtitle-qc-console:calibration:v1` 为键保存在浏览器 localStorage，启动时自动恢复（数据损坏时静默忽略）；事件流状态不持久化，刷新后由重放重新构建。

## 自动化测试

`src/__tests__/` 共 41 个用例，覆盖需求要求的全部场景：

- **乱序补齐**：缺口出现/消失、播出序号不越过缺口、补齐日志
- **重复去重**：事件 ID 级去重、内容级去重，均不产生第二条字幕
- **版本更新**：未锁定片段应用修订、过期版本被忽略
- **锁定冲突**：不静默覆盖、锁定时禁止编辑、「保留人工」与「接受机器」两种裁决
- **插值与外推**：两锚点线性插值、多锚点分段斜率、锚点处连续、首末段外推、单锚点不启用
- **非法锚点**：源/节目时间未严格递增被拒绝且保留原方案、冲突位置文案、未到达片段/非法时间码拒绝、修正后生效、同序号不产生副本
- **修订身份保持**：修订后锚点保留并跟随新源入点、重复事件不动校准方案、锁定冲突与裁决全程不丢锚点
- **校准后预览**：校准窗口与偏移、播放头命中（左闭右开）与落空、晚到补齐后自动重算、未校准时按源时间预览
- **会话级状态**：播放头设置与钳制、reset 保留锚点与播放头、本地恢复的清洗/去重/幂等
- **无残留重放**：reset 后事件流状态与初始状态逐位相等；同操作序列重放结果一致；播放器两轮完整播放终态一致
- **播放器行为**：按时间表投递、暂停结算剩余时间、倍速重排程、单步与播放混用
